# AI 関与の表示ルール

このリポジトリのマークダウン文書を編集・作成する際は、ドキュメントの冒頭（タイトル直後）に AI の関与を示す注釈を挿入すること。

## 既存文書を AI で添削・加筆した場合

元の文書は人間が書いたものであるため、以下の注釈を blockquote 内に含める:

```markdown
> 🤖 Originally written by hand, revised with AI assistance.
```

## AI が全文を書いたレポートの場合

AI が最初から全文を生成した文書には、以下の注釈を blockquote 内に含める:

```markdown
> 🤖 This document was generated by AI.
```

## 図解の活用

処理フロー、関数呼び出しチェーン、状態遷移など、図解するとわかりやすい内容には mermaid や UML を積極的に使うこと。テキストのフローチャートよりも mermaid の `flowchart` や `sequenceDiagram` を優先する。

## クリティカルリージョンの図示

ロックの取得・解放で保護されるクリティカルリージョンを説明する際は、ロックの範囲と保護対象の操作がひと目でわかるツリー形式の図を使うこと。ロック取得に `🔒`、解放に `🔓` を付けてスコープを明示する。

例:

```
mutex_lock(&dir->d_inode->i_mutex)     ← 🔒 ロック取得
    └── lookup_hash(&nd)                ← dentry の検索
        ├── dentry が存在しない場合
        │   └── __open_namei_create()   ← ファイル作成
        │       └── mutex_unlock()      ← 🔓 ロック解放
        └── dentry が存在する場合
            └── mutex_unlock()          ← 🔓 ロック解放
                └── O_EXCL なら -EEXIST
```

## パフォーマンス改善の知見の積極的な解説

古いカーネルや古い実装を扱う文書を添削する際、最新版でパフォーマンス改善（ロックの粒度変更、アルゴリズム変更、データ構造の刷新など）が行われている場合は、その改善内容を積極的に解説すること。改善の背景（なぜボトルネックだったか）、導入された解決策、新旧の比較を含めること。

## 脚注記法の活用

参考URLの参照やレポートの趣旨とは関係ない補足的な解説には、markdown の脚注記法を使用すること。本文の読みやすさを維持しつつ、参考情報や補足を適切に分離するためである。

```markdown
本文中での参照[^1]と補足的な解説[^2]の例です。

[^1]: https://example.com/reference
[^2]: この挙動は v5.10 以降で変更されています。詳細は commit abc1234 を参照してください。
```

## 人間が書いた注釈コメントの保護

コマンド実行の出力やソースコードに付けられた人間の注釈コメントは、なるべくそのまま残すこと。改変や追記が必要な場合は AI による変更であることを明示すること。

- **ソースコード内のコメント**: `🤖` を使う
- **マークダウン本文**: `🤖` を使う

例:

```c
/* ここでバッファを確保する */           // ← 人間のコメント。そのまま残す
/* 🤖 NULL チェックを追記 */            // ← AI が追記したコメント
```

```markdown
適当に grep して `ESC_BRACKETS` フラグを見つけた   <!-- 人間の記述。そのまま残す -->
🤖 `ESC_BRACKETS` は procps-ng の v3.x では `proc/escape.h` に定義されています <!-- AI が追記 -->
```
