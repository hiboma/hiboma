# ドキュメント添削スキル

指定されたマークダウン文書を技術的に調査・添削・追記し、レポートとしてブラッシュアップします。

## 入力

ユーザーからファイルパスまたはファイル名を受け取ります。

## 手順

### 1. 対象ファイルの読み込みと内容把握

- 対象ファイルを読み込み、テーマ・構成・記述の粒度を把握します

### 2. 技術的な調査（subagent を並列で活用）

以下の観点で subagent を並列起動し、技術的な詳細を調査します:

- 元の文書で言及されているソースコード（カーネル、ユーザランドツールなど）の最新の実装を確認します
- 元の文書に記載されている仕様や挙動が現在も正しいかを検証します
- 元の文書で疑問形や未確認のまま残されている箇所を調査して解決します
- 関連する CVE、セキュリティ上の注意点があれば収集します
- 最新版でパフォーマンス改善（ロックの粒度変更、アルゴリズム変更、データ構造の刷新など）が行われていれば調査します

### 3. ブラッシュアップの実施

以下の方針でファイルを編集します:

#### 構成の改善
- タイトルを明確にします
- 冒頭に要約を配置します
- セクションの流れを「現象 → 原因 → 実装」の順で整理します

#### 文体の統一
- 「です・ます」調に統一します
- 口語的な表現（「どゆこと?」「他何かあるんだっけ?」など）を改めます

#### 人間が書いた注釈コメントの保護
- コマンド実行の出力やソースコードに付けられた人間の注釈コメントは、なるべくそのまま残します
- 改変や追記が必要な場合は AI による変更であることを明示します
  - ソースコード内のコメント: `🤖` を使います
  - マークダウン本文: `(🤖)` を使います

#### 技術的な追記と添削
- 追記・添削した箇所には `<!-- CC添削: 説明 -->` の HTML コメントを付けます
- 元の記述が不正確な場合は訂正し、その旨をコメントで明記します
- 元の記述が正しい場合でも、背景や詳細を補足できる場合は追記します

#### 古い調査への対応
- 調査時点の環境（OS バージョン、カーネルバージョンなど）をタイトルまたは冒頭で明示します
- 現在のバージョンで挙動が変わっている場合は、変更点を本文中で補足します

#### パフォーマンス改善の知見
- 最新版でパフォーマンス改善が行われている場合は、積極的に解説を追記します
- 改善の背景（なぜボトルネックだったか）、導入された解決策、新旧の比較を含めます
- 例: ロックの粒度変更（mmap_sem → per-VMA lock）、データ構造の刷新（rbtree → maple tree）、アルゴリズムの変更など

#### 図解の活用
- 処理フロー、関数呼び出しチェーン、状態遷移など、図解するとわかりやすい内容には mermaid を積極的に使います
- テキストベースのフローチャートよりも mermaid の `flowchart` や `sequenceDiagram` を優先します
- octmark は mermaid のレンダリングに対応しています

#### クリティカルリージョンの図示
- ロックの取得・解放で保護されるクリティカルリージョンを説明する際は、ロックの範囲と保護対象の操作がひと目でわかるツリー形式の図を使います
- ロック取得に `🔒`、解放に `🔓` を付けてスコープを明示します

```
mutex_lock(&inode->i_mutex)           ← 🔒 ロック取得
    └── 保護対象の操作                ← クリティカルリージョン
        └── mutex_unlock()            ← 🔓 ロック解放
```

#### 脚注記法の活用
- 参考URLの参照やレポートの趣旨とは関係ない補足的な解説には、markdown の脚注記法 `[^1]` / `[^1]:` を使用します
- 本文の読みやすさを維持しつつ、参考情報や補足を適切に分離します

#### 参考ソース・参考資料の併記
- 文書末尾に「参考ソース・参考資料」セクションを追加します
- ソースコードのファイルパス・関数名、コミットハッシュ、CVE、外部資料をテーブル形式で整理します

#### AI 関与の表示
- `.claude/rules/ai-authorship-notice.md` に従い、冒頭に以下の注釈を挿入します:
  ```
  > 🤖 Originally written by hand, revised with AI assistance.
  ```

### 4. プレビュー

- octmark でプレビューを表示し、ユーザーに確認を促します

```bash
cat <file> | octmark --name "<ドキュメント名>"
```
